## Decisions and upstream facts

Selected approach: repair existing adapters, protected engine journal, repository registry and command barriers in place. Reject a second supervisor or replacement state service: those would duplicate ownership without resolving external-effect ambiguity. Retain legacy durable identities and publication paths; require explicit safe migration when new proof is absent.

Official facts confirmed against installed Paseo 0.15.4 and Pi 1.5.2 by the independent researcher. Full source/accessor findings: `executor-outcome-research.md` (SHA256 `8e33a43ff6e63b3ff9687dd9cbe80aa3af9c745d6249f645e90b329b05ed8f3e`):

- [Paseo client, pinned source](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/client/src/index.ts): `await agent.refresh(); agent.current()` exposes the snapshot; workspace refresh returns its descriptor. Snapshot fields include provider/model/cwd/workspaceId/labels/activeTurn/persistence/runtimeInfo. Public snapshots do **not** expose runtimeConfig/providerOptions or original workspace source/base SHA. Do not invent these accessors.
- [Agent shutdown source](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/server/src/server/agent/agent-manager.ts) and [Codex transport](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/server/src/server/agent/providers/codex/app-server-transport.ts): successful archive acknowledgement follows awaited owned-provider shutdown and child cascade; shutdown timeout throws. `archivedAt` is persisted **before** close, so it cannot replace a lost acknowledgement. `waitForFinish` timeout only ends observation; status `error` can be observer/lookup failure, not provider termination.
- [Pi RPC documentation](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/rpc.md) and [agent session source](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/src/core/agent-session.ts): `started`/`queued` mean acceptance. `handled` starts no ordinary run, but extension/input hooks have already executed; it is **not** general proof of no effects. `agent_settled` has only `{type,aborted}`, no run ID or result. Exact correlation must be supplied by exclusively owned session/run state. Abort acknowledgement awaits abort and idle. Close stdin and await the owned child exit for cleanup; never signal an arbitrary persisted PID.

The repair therefore separates ordinary execution settlement from external-effect disposition. Pi handled must stop waiting immediately but hold unknown extension effects. Successful terminal collection is accepted only with exact-run proof; idle, archived timestamps, or last text alone cannot supply it.

## Frozen shared interfaces and ownership

**Lane E owns `ports.ts` and `types.ts` and lands interface definitions first.** Lane A consumes them, never edits those files. Lane R owns registry DTOs in `repository.ts` and adapter construction in `cli.ts`. Publish the exact interface patch to both lanes before parallel behavior edits. Existing JSON envelope and plugin public DTO remain compatible; no plugin changes are planned.

Define and validate `AdapterOutcome` in `ports.ts`, used by dispatch/inspect/collect/cancel and a typed adapter refusal error for failures before an execution ID exists:

```ts
type EffectDisposition = "none" | "accepted" | "unknown";
type TerminalDisposition = "nonterminal" | "completed" | "failed" | "cancelled" | "timeout";
interface AdapterOutcome {
  status: "running" | "completed" | "failed" | "cancelled" | "timeout" | "permission" | "uncertain";
  effect: EffectDisposition;
  terminal: TerminalDisposition;
  execution_id?: string;
  proof?: { kind: "preflight_refusal" | "run_receipt" | "process_exit" | "archive_ack" | "no_ordinary_run"; reference: string };
  result?: Record<string, unknown>;
  error?: string;
}
```

The proof reference is an opaque bounded ID (never a path, JSON receipt, or external identity supplied by a CLI/worker). It identifies protected adapter evidence, not caller-supplied authority. Lane A resolves it inside the configured role receipt root and verifies schema, canonical containment, ownership, task/packet digest, repo/delivery/role, execution/run identity and outcome. The engine accepts proof only from the configured trusted adapter resolver, bound to its existing execution intent; worker/CLI JSON cannot self-attest a proof. Lane E owns the `ExecutorPort.resolveOutcomeProof(outcome, expectedContext)` signature in ports.ts; Lane A implements it and Lane R constructs adapters with protected roots. Invalid or unavailable proof resolves to uncertainty. Protected evidence paths, Pi session paths, raw provider text and private receipt contents are omitted from public DTO/index/export projections; preserve only the existing sanitized status/digest/error allowlist. Runtime normalization rejects contradictory/unsupported tuples. `completed` requires accepted exact run and terminal completion proof. `none` requires proven pre-effect refusal. `unknown` always retains unresolved external disposition, even when an ordinary run is known not to exist. `permission` and observation timeout are nonterminal; they cannot release claims. Known accepted terminal failed/cancelled/timeout is clearable only with matching execution proof, not status spelling. Existing untyped/legacy responses without sufficient attestation are conservative unknown, never inferred completed. Normalized outcomes retain provider and execution metadata needed by existing manifest/producer verification. Domain stage/review result JSON remains inside `result`, separate from lifecycle status.

State fields added by Lane E store effect/terminal/proof references on exact execution records, plus durable cancellation intent tied to delivery and request digest. Older records load without rewriting identities or fabricating proof. All new agent and review task digests include canonical repo, delivery, stage/kind and existing attempt/candidate/revision inputs. Resume locates persisted current execution first; it does not compute a new digest for an old intent.

Lane R owns discriminated reservation DTOs. Every variant has token, start time, PID and process-start identity. Worker adds generation/owner token. Command adds action, delivery ID, request ID, input digest and phase `reserved|effect`. Cancellation is a separate typed record with delivery/request/input digest and phase `requested|reconciling|draining|complete`; it may coexist with an already-owned worker operation but excludes new operations. Exact request digest includes original expected revision and all semantic arguments. Completed identical request replay returns stored outcome before stale-revision rejection; changed input under the same request ID refuses.

### Pi

Pass required per-role protected `stateDir` from CLI (`executor-processes` / `reviewer-processes`); do not use provider-returned session paths as receipt roots. A generated opaque run ID indexes a fixed private file beneath that root. External identity encodes version/run ID; receipt contains canonical session file, task/packet/prompt digest, repo/delivery/role, session ownership and exact command ID. Validate schema, ownership, canonical containment and all identity fields on lookup. Provider output cannot create/choose a receipt path. Legacy session-only IDs remain readable as uncertain, never upgraded by idle text.

Serialize one active owned run per canonical Pi session globally across roles and profiles: Lane R supplies `sessionOwnersDir` from the single protected Toolkit registry root (`<registry>/pi-session-owners`), never from individual role receipt roots or RPC inputs. Lane A derives its key as SHA256 of the real canonical session path and acquires a short synchronous exclusive owner record there, containing role receipt-root identity, run ID, PID/start identity and token. All Pi constructors, including standalone foreground, use this same trusted registry root; reject mixed owner-root configuration for a configured process and do not permit per-adapter override. Different registry roots are separate explicit installations, not a supported shared-session mode; refuse adopting any session whose protected ownership provenance names a different installation. Existing sessions without provable exclusive ownership are held, not adopted. Retain private run receipts in per-role roots. A global owner record is a file protocol, not a daemon. Persist/fsync intent **before** sending prompt; retain it on response loss. Events can precede prompt acknowledgement: buffer them for the sole bound run, then reconcile acceptance without losing terminal events. `started`/`queued` accepted; `handled` settles the adapter as failed/no ordinary run with `effect:unknown`, a visible extension-effect diagnostic and no wait/automatic redispatch. Do not claim that closing Pi undoes extension effects. Unknown disposition stays uncertain.

Persist terminal receipt only from events correlated to the exclusively owned run. Capture bounded assistant text from this run; preserve attempt failures (`error`, `aborted`, `length`), failed retry finalError and compaction outcomes. A later successful retry may supersede a failed attempt; `agent_end` alone is insufficient. On exact `agent_settled`, atomically store final disposition/text digest and result. Active+idle, missing/corrupt receipts, lost settlement, uncertain session ownership and legacy IDs remain uncertain. Exact active+streaming/compacting is running. A settled receipt survives process restart without querying stale `get_last_assistant_text`.

Abort records exact abort request/ack and run disposition; unrelated/old aborted settlement is rejected. Await owned child shutdown on cleanup. Pre-prompt validation/model refusal with proof is `none`, cleanup in finally awaits any started child; after prompt may have reached hooks/run, uncertainty is retained. Crash after intent but before send without a durable no-send proof is conservatively unknown. No auto-redispatch. Do not recover a session for live/unknown previous owners. A fresh adapter reads exact protected terminal receipts without launching Pi. It must not spawn another RPC runtime against an active/unknown session merely to query state or abort: if the original owned stream cannot be reconnected, report running only with positive live evidence, otherwise uncertain, and preserve ownership. Dead parent without terminal receipt is unknown, not permission to resume a prompt. Existing same-process owned runtime supports abort and explicit subsequent run; terminal-receipt reattachment supports fresh-adapter inspection without another runtime. Do not add a daemon to force reconnection.

Persist identity/outcome before stage progression.

Cancellation first durably marks intent and prohibits new dispatch/check/publication progression. Post-await paths reread under existing state lock. **While cancellation is pending**, preserve newly returned external IDs, acceptance evidence and terminal receipts required to cancel/reconcile; do not apply manifests, advance stages or resurrect running status. **After claim release**, all late callbacks are no-ops/refusals with zero journal/state revision changes. Include checker/reviewer/publisher awaits, not only agent collect.

Cancellation cannot release while a dispatch has unresolved identity, provider work may be live, command effects are unresolved, or an owned operation can still return unreconciled evidence. ### Explicit E↔R cancellation and live-runtime protocol

Freeze these engine APIs in Lane E and repository coordination wrappers in Lane R before parallel behavior edits:

- `beginCancellation(context)`: synchronous engine-state transaction validates exact request/grant/revision and persists cancel intent; returns cancellation epoch/request digest and outstanding operation IDs. It neither invokes providers nor releases claims.
- `reconcileCancellation(context, ownedAdapters)`: asynchronous operation running in the process that owns live adapter streams. Resolves exact in-flight dispatch IDs, records acceptance/terminal receipts while cancelling, invokes exact owned adapter cancel once per durable intent, and returns protected-journal reconciliation status. It never releases the claim. Reentrant worker/tick callbacks merge by execution ID and cancellation epoch rather than overwriting snapshots.
- `finalizeCancellation(context, repositoryFence)`: synchronous final transaction verifies the matching cancellation epoch, all terminal dispositions, zero outstanding worker/command operations, and stopped/drained owner acknowledgement; releases claim once and commits request result. No caller-provided boolean can attest drain: Lane R resolves repositoryFence against protected current reservation tokens/generation under lock.

The workspace-command process obtains the repository cancellation reservation and calls beginCancellation, then waits/observes durable status. If a live runner owns Pi, it must **not** construct another Pi runtime or try to cancel through a cloned adapter. Lane R runs a cancellation watcher concurrently with the worker's dispatch/collect await, using the same configured engine/adapter instances as that worker. Watcher observes durable cancellation epoch, calls reconcileCancellation outside locks, and records acknowledgement. Acceptance arriving after cancel intent is preserved and then cancelled; watcher and main await callbacks join on the same protected execution ledger. Polling watcher cannot overlap itself. The watcher remains active while pausing/stopping. If the owning process is lost, takeover uses protected terminal receipts/provider exact reconciliation only; an inaccessible live Pi stream stays uncertain, never a second runtime.

Lock order for combined transactions is **repository session lock → engine state lock**, and reverse acquisition is prohibited. No provider/adapter await or process wait occurs while either lock is held. begin/reconcile receipts use short separate engine transactions; final release alone acquires repository fence then engine lock synchronously, rechecks all tokens/epochs/acknowledgements and journals result. R owns the outer wrapper and calls E's finalize inside it. No engine method calls back into registry while holding engine lock. Cancellation owner death permits only same-request token takeover; worker watcher binds durable request epoch (not transient CLI PID), so a replaced observer does not duplicate cancellation. Standalone foreground uses the same watcher and lock protocol.

Stop selects graceful runtime drain: it blocks new stages but keeps the original controller and owned Pi stream alive to observe settlement and persist terminal receipt; it never closes stdin or aborts a still-active run just to exit. Native status remains stopping until the owned run settles, receipt is durable, child exits orderly, and controller exits with exact owner acknowledgement. No detached unowned Pi child and no false stopped acknowledgement. Cancel during stopping is handled by the concurrent watcher and may terminate the exact owned run. On normal settlement Stop preserves unfinished delivery for explicit Resume; the new controller reads receipts and continues the same delivery under pins, never repeats the old prompt. This retains the existing one-shot controller model without a daemon. A permanently unprovable run can remain uncertain/stopping; it is not reported stopped.
