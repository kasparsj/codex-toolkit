# Local-only implementation interfaces

Current user correction excludes GitHub App. Only this local developer-mode interface is active.

- Engine: Node/TypeScript, explicit private state root, canonical repository/run ID, revision and request ID. Current package modules expose core/policy/reviews/store/engine/CLI/projection. No Python/Spec Kit runtime calls.
- Publisher: `new Publisher({repo, repositoryId, login, actorId, stateRoot, remoteUrl, ...})`; repo is owner/name, remoteUrl canonical HTTPS. Test-only transport/token injection is explicitly gated. `execute(packet)` supports `preflight`, `publish_plan`, `publish_implementation`, `publish_issue`, `list_reviews`, `finalize`. Writes require exact expected payload and `authorized_digest`; finalize is read-only and returns human action states. Publisher owns trusted Git and intent/readback; no App authentication.
- Engine owns trusted local profiles and publication policy, proposal spool, exact digest grants, source-derived view, foreground scheduling/serviced IDs, gates and state. Publisher rechecks selected human actor/repo before writes. Both use owner-controlled state, never expose raw tokens/configuration.
- Executors: subprocess JSON packet, public Paseo adapter and direct Pi JSONL. Real actual provider execution remains acceptance evidence. Worktrees isolate edits; provider settings define local permissions. No App sandbox promise.
- Native plugin: actual SDK 0.15.4, React Native theme/compact primitives, shared typed RPC, safe backend CLI argv/profile. Client supplies only registered IDs, permitted action, exact expected revision/request ID/draft digest; never filesystem paths, credentials, policy or executables.
- Repository plugin entry: workspace-scoped `/delivery` calls the SDK's `openPanel("delivery")`. RPC sends only `workspaceId` and action data; the server refreshes the live Paseo workspace, obtains its directory from the host SDK, and passes that server-derived directory to the portable CLI. Setup is the sole exception that accepts protected asset paths, and it validates them before creating a binding.
- Portable repository commands: `workspace-status --directory`, `workspace-setup --directory --expected-revision --request-id` with one JSON stdin object, `runner-control --directory --expected-revision --request-id --action`, and `workspace-command --directory --delivery-id --expected-revision --request-id --action`. Envelopes remain `{ok:true,data}` or `{ok:false,error}`. Repository identity, setup, runner observation and safe run projection remain usable without Paseo.
- Repository runner: durable versioned records outside Paseo bind canonical GitHub identity to exactly one profile/state root. Transition reservation and pause/stop barriers linearize under one repository lock before external work. The plugin starts/observes a trusted fixed Node entry; panel lifetime never owns the runner.
- Local controls are authorized to trusted authenticated host clients only when owner-controlled backend config enables them; default read-only. This is not per-user OAuth and cannot substitute for independently verified GitHub reviews.
- CLI families: bare/run, start/issue/rank, list/status, pause/resume/recover/cancel, correction, draft issue/list/show/publish, publish/bind PR handoff, export/inspect-export. Default output is safe bounded JSON; CLI explicit draft show may reveal its protected content. User asks for full replacement, not exact preservation of obsolete App flags.
- Publication defaults off; independent explicit/automatic PR and issue modes require configured local policy. Mark-ready, label application, review, merge and deploy are not publisher operations.
